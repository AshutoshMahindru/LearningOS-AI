# WP-111: LearningOS V3 Product Constitution

## 1. Product Mission & Purpose
LearningOS is an adaptive, local-first ML/AI apprenticeship operating system. Its purpose is to transform ambitious builders into world-class **AI Systems Architects/Engineers** who can build, inspect, debug, challenge, evaluate, and direct complex AI systems—including code generated by autonomous AI agents.

## 2. Core Invariant (The Whole-System First Law)
> **"Start with the useful whole. Map it. Interrogate it. Descend only to the narrowest blocker. Decompose it. Rebuild it. Break it. Explain it. Transfer without AI. Prove competence. Return to the system."**

## 3. Controlling Principles

### I. Competence Over Activity Completion
- Navigating screens or running code cells does not constitute learning.
- Advancement across missions is gated exclusively on accepted, rubric-evaluated evidence.
- Evidence submission is not evidence acceptance; rigorous automated checks and transfer assessments govern certification.

### II. Schema-Driven Genericity
- Zero bespoke UI pages or custom API endpoints per mission.
- Every mission is a declarative specification rendering through a controlled, standardized stage component catalogue.

### III. Radical Epistemic Honesty (No-AI Certification)
- No-AI stages disable all LLM assistance, hints, and copilot autocomplete at the runtime execution level.
- True mastery requires transferring principles to fresh, unseen cases without automated assistance.

### IV. Local-First Sovereignty & Privacy
- All learner code, data, models, reflections, and progress reside on the learner's local machine under `~/.learningos/`.
- The platform functions fully offline; remote LLM APIs are optional enhancements.

### V. Controlled Failure & Targeted Repair
- Failure is an explicit pedagogical tool, not an exceptional error.
- Partial gate failure does not trigger wholesale mission repetition; it generates bounded, precision repair tasks addressing the specific missing competency.

## 4. Product Non-Negotiables
1. **Never hide a broken system**: System errors and stack traces must be surfaced through structured diagnostic tools.
2. **Never leak answers**: Socratic tutors must guide through questioning, never providing copy-paste solutions.
3. **Never couple learner data to curriculum git trees**: Curriculum repos are strictly read-only distribution packages.
4. **Never advance without evidence**: Competency progression requires verified evidence linked to code hashes and attempts.
